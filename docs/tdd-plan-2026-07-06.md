## Temuan Critic (verdict: perlu-perbaikan)

Yang harus ditangani sebelum/selama eksekusi — diringkas dari agen `critic:completeness`:

### Test yang berisiko vacuous (HIJAU tanpa membuktikan fix)
- **WS-1** — menu.tsx tidak membaca `.length` pada data async; `score ?? null` sudah menjaga di baris 228. Test mount→unmount→remount akan lolos pada kode saat ini. **Wajib** dapatkan repro `reading 'length'` nyata (langkah 5) sebelum menulis test.
- **WS-3c** — layar sudah render benar saat `id` ada. Test dengan `useLocalSearchParams({id:'inst-1'})` lolos pada kode saat ini. Slice yang benar-benar bisa diuji: `id===undefined` (param loss pada direct URL web).

### Cakupan WS-2 kurang di layer yang tepat
- **onAddPress bypass** — `CompactActionRow:425` = `onAddPress ? onAddPress() : past ? showPastPeriodAlert() : onAdd?.()`. Saat `onAddPress` di-set (Goal→+KPI Area `:805`, Strategy→+initiative `:578`), cabang past dilewati total. `pastLocked` di row perlu tapi **tidak cukup** — callback `onAddPress` sendiri harus gating. Test harus di layer tombol.
- **Kontrak a11y bentrok** — plan meng-assert `accessibilityState.disabled=true`, tapi mekanisme fix = press→`showPastPeriodAlert()` (tetap ada handler, bukan Pressable disabled). Samakan: pilih satu (dim + alert-on-press ATAU disabled), lalu assert yang konsisten.
- **Sumber label switcher** — pastikan `period-switcher` benar-benar menerima `focus` + `now` untuk menghitung status, atau label di-pass sebagai prop (assert-nya pindah ke parent).

### WS-3d — sinyal mismatch berisiko salah invariant
- `listInstances` tidak ber-window; `get_repeat_compliance.expected_count` ber-window (unknown). Tiga kasus hook mem-mock kedua sisi independen → **tidak akan menangkap window mismatch nyata** (hanya menguji aritmatika input mock). Baca definisi RPC dulu.
- Perbandingan hanya `expected_count > length`; arah sebaliknya (`length > expected_count`, all-time vs today-window) tak tertangani → bisa lapor "consistent" padahal UI kontradiksi. Instance-detail `[id].tsx:74` memfilter today client-side — skenario over-count sangat mungkin.
- Penyebab paling mungkin di produksi (compliance>0, list kosong) = **RLS menyembunyikan baris** dari user, sedangkan RPC SECURITY DEFINER tetap menghitung → hanya tertangkap **DB contract test**, bukan unit hook. Belum dijadwalkan.

### Concern infrastruktur
- **expo-router mock** — `home.test.tsx:40` membuat `push: jest.fn()` baru tiap panggilan (tak bisa di-assert). Fix mockPush modul-level benar, tapi mock harus mempertahankan semua export yang dipakai subtree (`Href`, `Stack`, `useLocalSearchParams`, `Link`) atau import throw saat load.
- **react-native-css** — `instance/[id].tsx` & `workspace-screen` impor dari `react-native-css/components`; jest-expo tidak auto-mock. `workspace-screen.test.tsx` greenfield (belum ada preseden render) → renderability belum terbukti.
- **Type-check** — field return baru `useRepeatInstances` & literal route baru = tsc-caught, bukan jest-caught. Jalankan `type-check` sebelum menyatakan selesai.
